## 普通角色配置导入

未发现本次游戏更新导致普通角色导入协议失效的证据：

- 最新客户端仍连接同源 `/ws`，当前 URL 增加 `w=1` 等查询参数，不影响脚本按 host/pathname 识别。
- 最新 `qI` 解码器仍解析 JSON `{tick,m}`；`TI` 仅展开其他玩家 `move.path` 与 `enter.player.path` 的压缩路径，不改变本角色数据。
- 最新客户端 `welcome` 与 `snapshot` 仍读取 `you` 和 `windows`，独立 `windows` 消息仍读取 `windows`；公会初始身份仍来自 `welcome.guild`。
- 普通角色脚本没有游戏资源文件名白名单；新增完整角色字段不会使现有捕获结构检查失败。

本次运行普通导入回归，覆盖完整/部分字段、食物选择、药水、公会、世界窗口、失败原子性、连接替换、异步 GM 存储及 DOM 桥接。此结论基于公开源码和隔离回归，没有使用真实账号或 Tampermonkey 实机，不能保证所有实际环境均正常。

## 战斗模拟需要同步的变化

已明确发现回仓取食后的进食行为变化。旧函数 `xB` 取完食物直接将 activity 置为 idle；新函数 `Sq` 在取食后加入最多 64 次自动进食，直到一次调用未改变血量：

```js
for (let n = 0; n < 64; n++) {
  const i = a.hp;
  if (j3(a, o), a.hp === i) break;
}
```

`j3` 仍按角色进食阈值、存活状态和可用食物决定是否进食；并非无条件补满血量。攻击面板相同不能保证小时收益相同。

从新版完整资源使用 AST 与作用域依赖分析，在临时目录原样提取独立原始预测模块（最终 600 个声明，含诊断用导出），没有改动正式 vendor、提取器或生成模块。比较三流派 85 级示例 × 20 普通怪物，共 60 组旧/新原生一小时预测完整返回对象；59 组一致，魔法流派对怪物 12（Ash drake）出现差异。共同输入：角色 id 127、seed 314、lastTick 1500000、仓库存有食物 64/65/66 各 100、锁定 65、自动选食、guildBonus .095、世界窗口从 1000000 到 1006000，xpMult 1.1、rarityMult 1.2。
