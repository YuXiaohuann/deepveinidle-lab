# Legendary 选择后空白反馈排查

调查日期 2026-10-30；结合 2026-10-31 用户补充的 Opera 截图更新判断。初轮本地提交 `0c95ee2`，生产目标 `https://dvi-lab.pages.dev`（当时页面显示 1.9.1）。仅调查，未修改功能、未部署；初轮专项不代表后续版本重跑，也不代替完整发布验收。

## 结论与范围

反馈原文：“Your SIM is really great, but right now, when I select ‘Gear Legendary,’ a blank tab opens—it's glitching.”

用户已确认使用 Opera。截图明确为战斗页 Body（胸部）Meteoric plate · 85、Legendary、强化 +12 的原生品质菜单展开场景：五个选项可读，Legendary 高亮；白色矩形从菜单左上角位置向右下方大幅延伸，覆盖部分战斗结果，右侧仍有结果可见。这不是截图意义上的新标签页或整页白屏，更符合原生下拉弹出层尺寸／绘制异常。截图本身不能证明计算停止，也不能证明只有 Legendary 才触发。

2026-10-30 初轮分别检查战斗装备品质、价格弹窗的装备与传说筛选，以及采集、制造、强化品质入口，均未复现。该轮通过 selectOption 驱动 change 事件，没有验证用户实际展开的 Opera 原生菜单，因而不能排除截图中的问题。

## Opera 原生弹出层判断

- 当前 `src/app.js:58` 使用标准 select 和五个 option；`src/style.css:2` 提供暗色 color-scheme、背景和文字颜色，没有自定义白色菜单面板。桌面双列配置区使用 overflow-y:auto，可能是复现环境的一部分，但尚无证据将滚动容器认定为根因。
- Chromium 官方问题 [569964134](https://issues.chromium.org/issues/569964134) 的标题描述了 Windows 原生 select 弹出层大于选项区域并留下白色空白，涉及 device scale 1.1；其关联的 [566683388](https://issues.chromium.org/issues/566683388) 中还可见同时引用 `567129341` 和 `569964134` 的上游回退修复记录。该证据支持“已存在同类上游弹出层缺陷”，不能据此认定用户的未知 Opera／Chromium 版本命中该缺陷或已经包含修复。
- 结合截图，优先排查 Opera／Chromium 原生菜单尺寸与缩放，其次是图形合成／驱动和主题兼容性。单纯给 option 增加深色背景不一定能改变错误弹出层的尺寸；现有证据也不足以支持全站切换自定义下拉框。
- 品质 change 后整应用重绘仍是一般性故障暴露点；但截图中菜单保持展开、页面结果仍可见，没有证据表明此时已经触发 change。该方向不再是这张截图的首要解释。
- 本机仅有 Chrome，没有安装 Opera；2026-10-31 只执行源码与样式核查、截图分析和官方资料核对，没有新增 Opera 实机或浏览器验证，不将初轮测试改称本轮通过。

## 可疑位置与原因判断

| 现象／位置 | 已核对事实 | 仍需排查的原因与限制 |
| --- | --- | --- |
| 原生菜单旁大片白块 | Opera 截图中菜单选项可读，白块从菜单区域向右下方延伸，其他页面区域仍可见；存在高度相似的 Chromium 上游记录。 | 优先核查浏览器／内核版本、页面与系统缩放、显示器 DPI，其次对比图形加速与主题。用户版本未知，未实机复现，不能锁定上游缺陷编号。 |
| 当前页面或结果区域空白 | `src/app.js:114` 每次品质 change 调用整应用 `render()`；`render()` 重建 `#app`，并依次渲染隐藏的采集、制造、强化、精通等页面，再计算战斗结果。此流程无统一异常展示。 | 同步异常可中断后续渲染，留下空结果区或未完成界面；其他页面状态也扩大了影响范围。这是实现上的故障暴露点，本次未找到实际抛错数据，且不能解释真正的新标签页。 |
| 手机／Safari 下拉选择异常 | 控件在 change 中被整体替换，随后对新控件执行 focus。 | 浏览器原生选择器与 DOM 替换／焦点恢复的兼容性值得专项检查；本次 selectOption 事件检查未覆盖真实原生选择面板、Safari 或 iOS，不将此假设写成已确认浏览器缺陷。 |
| 价格弹窗空白／卡顿 | `src/item-price-controls.js` 在筛选时同步重建整个弹窗与全部结果行，没有分页。当前样本最多 332 行，未卡顿或报错。 | 更大历史报价／手工价格集合或低性能设备可能产生主线程长任务；这不能解释新增标签页，也未在本次复现。强化限制清空不会生成所有强化等级，只包含现有集合及当前基础候选。 |
| 传说品质数据缺失 | 118 件装备的传说数据与 1,416 组属性检查正常。 | 当前证据不支持“Legendary 普遍缺失导致白屏”；旧版本、特定账号数据和未覆盖入口仍不能排除。 |

存储写入失败已有捕获与保存失败提示，战斗 Worker 创建／运行错误也有结果区提示，因此二者不应直接等同于新增空白标签页。资源加载或旧缓存可影响整个应用启动，但本轮生产资源请求正常，没有证据将其与 Legendary 特定关联。

## 后续定位顺序

1. 在 Opera 的 Update & Recovery 检查更新并重启；从 `opera:about` 记录 Opera／Chromium 版本和操作系统。操作入口见 [Opera 官方 FAQ](https://help.opera.com/en/faq/)。不能保证更新后必然修复该问题。
2. 先按 Ctrl+0（macOS 为 Command+0）将网页缩放恢复为 100% 后重开菜单，对比其他品质、其他下拉框。若仍异常，再记录系统显示缩放和多显示器情况，用不同 DPI／缩放条件对照；这一步是针对上游相似缺陷的诊断建议，不是已验证修复。
3. 再对比图形加速开关，切换后重启浏览器。Opera 官方 FAQ 对图形问题提供开关加速的排查建议，但并未声称它可以修复本项目的 select 问题；无改善应恢复原设置。
4. 以同一装备、品质和强化 +12，在 Opera 原生菜单展开状态对照 Chrome／Firefox，以及无扩展会话。观察 Escape 关闭菜单后白块是否消失；这比仅触发 selectOption 更能确认弹出层归属。
5. 若需要网站侧绕过，先制作保留暗色样式与滚动容器的最小复现，逐项对比纯原生 select、容器布局、缩放及焦点行为，再确定局部改动。不先调整战斗计算，也不在缺少验证时宣称 CSS 或自定义控件已修复。
