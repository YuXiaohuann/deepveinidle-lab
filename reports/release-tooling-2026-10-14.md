# 发布工具优化实施与验证

日期：2026-10-14。已按用户确认方案实现；应用版本仍为 1.2.4，未提交、部署或改变计算规则。正式操作见 [发布流程](../docs/release.md)。

## 实现范围

- 增加 `release:check`、`release:package`、`release:verify` 三个入口。日志与机器证据保留在独立目录；成功只输出摘要，失败保留非零退出、异常位置和完整诊断。
- 发布检查编排完整测试、唯一完整独立对照、隔离生成、语法／版本／文档链接／路由定义及本机 HTTP／浏览器验收。原全部页面审计原样迁为 `scripts/native-audit.mjs`，日期型原文件保留历史身份；不额外执行其战斗子集。
- 打包依赖完整通过证据及输入／环境摘要；只创建新目录，清单留在证据目录。拒绝隐藏／非应用文件、符号链接、既有目录、过时证据、额外文件和内容变化。
- 目标验收必须明确 URL，并检查来源包与当前输入，执行十五路由、所有资源摘要、HTML（只允许已知 Cloudflare analytics loader 注入及标签间空白）、七页双语两视口、滚动／键盘／边界／页脚和全部普通战斗完成。
- 固定 playwright-core 1.62.1；浏览器默认使用系统安装，可由 RELEASE_BROWSER 指定。不依赖个人运行时缓存，使用隔离上下文，不触碰用户已有会话。输入摘要涵盖应用／上游、脚本、测试、文档与报告、依赖清单及已安装直接依赖版本、Node 环境、浏览器可执行文件摘要与配置。

## 本次实际验证

发布工具专项测试覆盖成功／失败编排、完整日志、超时、缺失 TAP 总结与失败／取消／跳过、文档锚点、输入变化、白名单、已有目录、符号链接、额外文件／变更字节，以及 HTTP 路由跳转、资源和 HTML 替换拒绝。最终12项全部通过，零失败、取消或跳过，日志为 `/private/tmp/dvi-release-tools-final.log`；实现过程中发现嵌套 Node 测试继承上下文导致输出格式异常，已隔离该上下文并通过成功与失败编排验证。

本机浏览器与 HTTP 实跑通过：十五路由、47 个资源摘要、28 组中英文桌面／窄屏布局、滚动位置保留、键盘、滚轮边界、页脚及20个普通战斗目标。首次位置断言在键盘滚动尚未结束时读取位置失败；修正为等待滚动到边界、随后在稳定中间位置检查保留，保留原验收要求，重跑通过。原失败截图／诊断及后续通过证据分别保留在临时验收目录。

隔离提取实际通过：两次生成一致，生成代码及 manifest 与当前仓库逐字节一致；未知摘要明确拒绝且原输出保持不变，工作树生成文件未被改写。`scripts/native-audit.mjs` 与原全部页面审计脚本逐字节一致；此次未重跑其长时原始计算。

静态检查通过：89个 JavaScript 文件语法、59份文档的317个本地引用／锚点及版本、路由定义一致；`git diff --check` 通过。

本次未运行完整应用测试及独立原始计算长时对照，未对生产站点运行 release:verify，也未调用 Wrangler。完整 check 的编排使用隔离小型测试工程核验成功及失败路径；该工程的模拟步骤仅验证发布工具编排，不作为应用发布通过证据。当前实现仍须在正式发布前针对最终候选输入运行完整 release:check，再打包和分别验收部署地址／生产别名；不伪造本轮完整通过记录。

## 消耗与限制

完整 TAP、逐项资源检查和截图不回传到日常对话；机器结果及日志落盘，终端只给摘要。与此前估算不同，这次已运行检查的是工具专项和本机矩阵，没有可对比的完整发布实际 token 账单，不能把输出压缩比例当作模型总 token 节省。

基础浏览器矩阵和快照不替代改动页面专项或必要的人工视觉审阅。完整日志、截图、摘要清单与失败记录需要随发布证据保留；临时目录会被系统清理，正式发布时应选仓库已忽略的 .test-artifacts 目录并按需要另行保存。
