# 精通计算结果保留与双栏保存调研

日期：2026-11-08。本文保留实施前的调研建议；用户已明确采用两个固定保存栏位：一个手动保存，一个每次计算自动保存最优方案；不需要手动保存与计算结果之间的对比功能。后续本地实现与本次实际测试见[实施报告](mastery-result-slots-implementation-2026-11-08.md)，现行规则见[精通页面](../docs/pages/mastery.md)。本文调研内容不作为发布证据。

## 结论与范围

采用两个固定栏位，不增加命名方案库和无限历史：

| 栏位 | 保存内容 | 覆盖时机 |
| --- | --- | --- |
| 手动保存 | 用户选中的一项完整方案，包括装备、计算条件和结果 | 点击“保存到手动栏”时覆盖；不随导入、计算或应用自动变化 |
| 自动保存 | 最近一次成功计算的最优方案，包括装备、计算条件和结果 | 新计算成功且结果校验通过后覆盖；失败、取消、刷新、导入均保留原值 |

典型流程：装备 A 完成计算 → 将最佳或某个备选保存到手动栏 → 更换装备 B 并重新计算 → B 的最佳写入自动栏 → 切换查看 A、B。只有两个长期保存位置；用户需要保留其他结果时，后续可另行考虑文件导出，本轮不扩展。

本轮仅新增本报告及报告／后续范围入口，不修改运行代码、存档或现行设计。实施前需先将确认后的交互与验收同步到精通页面设计，并核对共用持久化规则。工作树原有文档改动保留。

## 现状与丢失原因

以下为本次源码核对所得，未执行浏览器复现：

- `src/mastery-controls.js` 与 `src/mastery.js` 保存模式、总点数、当前等级和目标等级；优化结果没有进入该存档。
- `src/mastery-optimizer-controls.js` 的 `result`、`fingerprint` 和目标／任务／档位选择均为模块内存变量。刷新会重置这些变量，因此即使下方目标等级仍在，结果收入、推荐卡片和计算条件也无法恢复。
- `signature()` 比较精通输入、对应来源配装及搜索选择；输入变化后 `invalidateMasteryOptimizer()` 调用 `clear()`，后者同时终止任务并将 `result` 清空。导入导致总点数或当前等级变化时会走该路径。相同数据的重复导入并非必然清空结果，需以实际输入差异判断。
- 模式、任务、目标或档位控件直接调用 `clear()`；开始新计算也先清空结果。当前“终止运行”和“删除已完成结果”耦合。
- `src/mastery-optimizer.js` 返回最佳及最多两个备选、各候选复核样本、原配置基线、种子、时刻等；不返回完整来源装备和价格。只保存返回结果不足以解释或恢复原计算条件。
- 当前设计明确规定输入失效时清除结果、完成结果仅会话保留。此需求属于行为调整，不应只补一处 localStorage 写入而保留冲突的失效规则。

## 两栏交互建议

### 展示与保存

在计算面板中、当前结果区域附近放置“手动保存”“自动保存”两个固定入口；选中后查看该栏的装备摘要、任务、总点数、计算模式、计算时间与结果。每次展示选中栏位的内容，桌面与窄屏均支持切换查看，无页面横向滚动。

空栏显示“尚未手动保存”或“完成计算后自动保存最优方案”。新计算期间仍能查看两栏旧结果，同时显示进度，不能把旧结果误标为本次运行结果。

当前计算结果仍保留既有前三推荐卡片。每项提供“保存到手动栏”，明确保存哪一项；“自动保存栏”始终保存排名第一项，不随用户应用备选而改写。保存整套计算条件及所选方案，单栏无需存整次搜索的缓存、模拟明细和全部备选。

手动栏有值时按钮文案改为“覆盖手动保存”；点击即执行这个明确动作并提示结果，不增加重复确认。自动栏显示“最近一次计算最优”，避免暗示它优于手动栏。保存时间与计算时间分开：手动保存旧计算不改变该结果的计算时间。

### 刷新、导入与变化提示

- 刷新恢复两栏数据和上次查看的栏位；有保存结果时提供明显的结果摘要与查看入口，不能因计算面板默认折叠而让用户误以为结果消失。查看无需计算，也不自动应用目标等级。
- 导入继续按既有规则更新当前精通配置，不覆盖两栏。与保存快照不同则提示“当前配置已变化，以下为保存时结果”，展开后列出点数／等级／配装等变化类别。
- 同样输入的导入不应使快照变成不可用；非法导入保留当前配置、两栏和原结果。
- 价格变化保留旧收入，提示使用保存时价格。精通产出评分不因价格变化失效；时间推进不会自动重算，始终显示原计算时刻与增益条件。
- 清空当前精通配置只清当前编辑配置，两栏继续保留；分别提供明确的“清除手动保存”“清除自动保存”入口，避免借配置重置误删成果。

### 查看、应用与重算

切换栏位只切换展示，不覆盖战斗／采集页，也不修改当前精通等级、总点数或目标。

保存结果的“应用到目标等级”仅在当前计算条件与快照匹配、版本兼容且现有预算／等级校验通过时可用。输入不同则保留只读查看并提示重算；不把旧结果应用到新条件下冒充有效优化。推荐应用继续复用 `applyMasteryRecommendation()`，保留剩余点数模式下限、预算、原子更新和保存失败提示。恢复／查看存档不能触发自动应用。

重算入口默认使用当前战斗／采集页配装，按钮写为“按当前配置重新计算”；展示差异，避免用户误以为正在计算所查看的旧装备。用保存配装重新计算属于可选后续扩展，首期不增加跨页装备恢复或隐式配置覆盖。

计算完成时沿用当前自动应用最佳的行为，但自动栏保存与自动应用独立：结果通过校验后先尝试保存快照，再执行既有应用。应用失败不能删除已完成结果；保存失败明确提示“本次最优未保存，刷新后可能丢失”，保留内存结果和旧持久化栏位，不声称保存成功。

## 保存内容展示

选中栏位后显示所选方案的 24 小时收入或精通产出评分、累计投入及计算条件摘要，可展开查看十项精通等级与保存时装备的品质、强化等信息。旧结果始终使用自身快照，不用当前页数据渲染旧装备。

不增加两栏并排对照、指标差额、相对提升百分比或优胜判断。既有推荐卡片中相对于该次计算原配置的差异及波动提示保持现行规则，不扩展为保存栏之间的比较。

## 存储与实现建议

复用现有浏览器本地保存方式，新增独立且有版本的双栏存档，不把优化记录塞进角色配置。单个 JSON 包含两个槽、修订号及选中栏位；每次写入先校验并序列化，再一次 `setItem`，失败时保留原存档。选中栏位的保存失败同样应有提示，不隐藏异常。

每栏至少保存：

- 计算时间、保存时间、存档格式版本、计算兼容版本及游戏资源标识；发布版本作为辅助展示，不能替代计算兼容版本。
- 目标、怪物／采集任务、分配模式、搜索档位、固定时长、总点数、全部当前等级。
- 实际提交给优化器的对应战斗或采集场景快照，包含装备及影响模拟的等级、消耗品、家园、增益、初始仓库等；只保存相关来源，不保存完整导入角色、库存或无关页面配置。
- 收入目标所使用的有效价格快照；精通点数目标无需价格。快照应由发送给 Worker 的请求白名单投影产生，避免 `optimizerInput()` 的展开参数携带另一页无关配置。
- 所选推荐的等级、成本、结果指标、原始基线及已有配对差异；保留有限搜索、原配置超预算或未完成等说明所需字段。

输入指纹从有效计算字段产生，排除语言、展示折叠、手动目标草稿、无关页面设置及非实际输入字段；当前 `signature()` 可作为拆分起点，但不宜直接拿原始对象 JSON 充当长期兼容协议。运行取消、当前条件匹配、历史结果兼容性分别处理，不再统一调用会删结果的 `clear()`。

仅保存两个紧凑快照，优先 localStorage；实际体积和写入阻塞需用合成最大配置测量后确认，未做本轮性能测量。若发现体积问题，先移除冗余和明细，再评估 IndexedDB，不预先引入数据库层。

坏存档／不支持的版本明确提示，不静默覆盖；结构可识别且数据可展示、但计算版本过旧时可只读查看并禁用应用。恢复不默认重算或改价。运行中刷新不承诺恢复进度，只保留上一次成功结果。多标签写入用修订号和写前读取检测冲突，发现较新记录提示重新载入，不以过期内存包覆盖另一栏；真正并发需用 Web Locks 等协调并测试，不能把 `storage` 通知等同于互斥。

## 外部资料与推导边界

- [Grafana 官方分享与快照文档](https://grafana.com/docs/grafana/latest/visualizations/dashboards/share-dashboards-panels/)区分实时链接、快照与导出。借鉴的是将已完成数据与实时数据来源分离；两栏及覆盖时机是本项目建议，不是该资料直接给出的结论。
- [MDN Web Storage API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API)说明 localStorage 跨浏览器会话保存、按来源隔离且读写同步。推导：可沿用本项目方案，但不能写入大规模搜索缓存；生产、Preview 和本机数据不会自动互通。
- [MDN 存储额度及清理规则](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)说明额度异常和浏览器存储边界。推导：界面应准确写“保存在此浏览器”，捕获保存失败；本地保存不能宣称云同步或永久备份。

本轮为源码与公开资料调研，未开展用户访谈或可用性实验。两个栏位来自用户明确选择，交互效率与性能收益尚未实测。

## 实施顺序与验收建议

1. 先更新精通页面设计的会话、失效、刷新、保存与应用规则，再拆分任务终止和结果保留，增加双栏存储及恢复校验。
2. 接入自动保存最优、手动保存选定推荐；加入两栏查看、差异提示和安全应用。
3. 执行保存、恢复与切换查看的相关单元及浏览器专项；发布另走完整三阶段流程。

必须覆盖：

- A 自动保存后手动保存 A，计算 B 后手动仍为 A、自动为 B；保存备选不影响自动栏最佳。
- 导入相同／不同点数与等级、刷新、离页、语言切换、编辑目标、清空当前配置后两栏内容正确保留，恢复不自动应用。
- 新计算进行中、失败、取消及迟到消息不覆盖自动栏；成功仅保存本任务最佳一次，配装变化后不能保存过期任务结果。
- 存储不可用、额度不足、损坏、格式／计算版本不兼容、跨标签冲突明确提示，保留可用内存结果和未被覆盖的原存档。
- 保存装备、价格与增益完整隔离；实时导入与价格自动更新不修改旧快照；两栏的收入和基线来自各自快照。
- 两栏仅切换查看，不生成跨栏差额、提升百分比或优胜判断；既有推荐卡片相对原配置的差异正常恢复，限定／不限制展示不改变应用校验。
- 双语、键盘和 390px 展示、无页面横向溢出；不修改战斗／采集配置；既有搜索规则不变。

本次实际验证仅为源码／设计核对及新增文档引用、差异检查，未运行应用测试、浏览器专项或发布检查。
