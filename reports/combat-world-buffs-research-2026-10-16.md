# 战斗配置导入全部生效世界增益调研

日期：2026-10-16。范围为现有本地代码与已核验游戏 1.0.1190 快照；本次仅调研并新增报告，未修改功能、当前设计规则或发布版本，未读取真实账号世界窗口，也未重新确认线上资源版本。

## 结论

遗漏同时发生在捕获和导入两层。应取消按 Weekly goal 名称筛选，并完整处理世界窗口的经验、稀有度两个效果；只删除名称白名单仍不能满足“所有实际生效世界增益”。不需要为活动名称维护清单，原始计算只依赖窗口时间与倍率。

建议首先采用与现有配置一致的“捕获时点生效倍率”语义：汇总捕获时实际生效的全部窗口，导入世界增益经验及新增的世界增益稀有度，作为可编辑配置全程参与模拟。这里的“实际生效”指捕获时有效，不承诺保留现实到期时间。若需求包含模拟期间按实际剩余时间失效，应另行确认时间窗口方案；两者不能混称。

## 已核验现状

| 环节 | 证据 | 行为及影响 |
| --- | --- | --- |
| 捕获 | `src/character-import.user.js` 的 `captureWorker/frame` | 旁听 welcome、snapshot、windows，保留全部窗口条目，但每条只保存 label/fromTick/toTick/xpMult；rarityMult 被裁掉 |
| 导入 | `src/character-import.js` 的 guild 分支 | 仅汇总名称严格等于 `Weekly goal: gathered`、`Weekly goal: felled` 且捕获时有效的窗口，写入 manual.weeklyXp |
| 规范化 | `src/manual-settings.js` 的 normalizeManual | weeklyXp 取整数；manual.windows 虽有默认值，但未从输入恢复，直接写入会被丢弃 |
| 模拟 | `src/manual-settings.js` 的 manualWindows、`src/simulation.js` 的 createScenario | 将 weeklyXp 构成覆盖整个模拟周期的经验窗口；已有到期时间不保留；稀有度固定为 1 |
| 其它消费者 | `src/work-import.js` | 采集／制造也有同样的 Weekly goal 白名单。本次要求为战斗，不能因修改共用捕获就宣称其它页面已支持全部世界增益 |
| 现有测试 | `tests/character-import.test.mjs` | Event 窗口虽被捕获，却明确未计入导入经验；对应预期需随新设计调整 |

旧脚本不能还原已经丢弃的稀有度字段。完整支持必须更新 userscript、刷新游戏重新捕获；不能将旧快照未包含 rarityMult 直接宣称为已确认无稀有度增益。兼容设计须区分旧捕获格式与新脚本中倍率确实省略的情况，建议增加捕获能力标记并在缺少能力时明确提示更新；是否升级桥接／协议号在实施设计时统一处理，不因旧桥接能连接就判定数据完整。

## 原始规则

依据 `vendor/game-original.js`，导出映射位于 `vendor/manifest.json`，生成模块已有相应语义导出，无需手改 `src/upstream.js`。

- `Ri`（windowModifiers）：窗口满足 `fromTick <= tick <= toTick` 时有效，两端均包含；不检查 label，不检查技能或活动类型。
- 未提供的 xpMult／rarityMult 默认为 1；各窗口增量分别加法叠加：`1 + Σ(mult - 1)`。同名条目也逐条参与，不能按 label 去重。只有倍率均为 1 的窗口对这两项计算无影响。
- `S8`：世界经验倍率参与战斗经验，与药水、祝福、公会、热门、精通等按原始 combine 规则组合。
- `w8`（combatRarityMultiplier）：世界稀有倍率参与战斗掉落稀有度计算；`src/combat-expectation.js` 复用该函数，因此正确传入 context.windows 后可沿用既有期望账本。
- 热门由独立的 mg／Yb 计算，并非依靠世界窗口名称识别。保留已有 game/current/off 行为；关闭热门不应关闭世界窗口，也不能额外把当前热门计入世界增益导致重复。
- 世界首领当前只做静态伤害／命中／DPS 估算；这两项世界窗口效果不意味着需要新增首领奖励模拟。

公开客户端可验证消费规则，不能列举服务器此刻下发的全部活动名称，也不能据此宣称服务器未来只会增加这两个字段。未知未来机制仍需重新核验。

## 建议修改清单

以下为待实施建议，不代表当前功能。

1. 先更新 `docs/pages/combat.md` 的导入、其它配置、全服活动边界与验收规则，再更新 `docs/technical.md` 的捕获字段、能力兼容和脚本版本说明。
2. 捕获层保留 rarityMult，保持窗口更新、跨连接隔离和字段最小化；增加足以区分新旧捕获能力的信息。
3. 战斗导入按 worldTick 判断全部有效窗口，分别汇总经验、稀有度，取消名称白名单。保留合法的小数精度，避免现有整数规范化吞掉小数加成；倍率校验范围应依据已核验规则明确，不能静默截断为另一数值。
4. 复用 manual.weeklyXp 作为世界经验存储以减少迁移，增加世界稀有度配置与双语输入；贯通默认值、规范化、清空、本地保存、文件导入和模拟窗口。旧普通配置缺少新项时默认 0；旧角色快照缺捕获能力时明确报告无法完整导入。
5. 世界增益仍独立于热门配置。有效空列表清零；格式缺失／异常按战斗字段默认回退并明确警告，不沿用上一角色的值，也不能因名称未知而跳过合法增益。
6. 只调整战斗消费行为；采集、制造、强化、精通验证共用脚本兼容性，未授权的页面规则不随之扩大。

若要求按剩余时间生效，则第 3、4 项须改为保存窗口、捕获基准 tick 和倍率，再相对映射到模拟时钟，保留到期边界，并定义重载配置后剩余时间是否继续减少、手动经验如何与导入窗口组合。现有 manual.windows 不能直接充当已可用接口；此方案还须明确是否导入尚未开始但会进入模拟区间的窗口。本次不建议在“全部当前有效增益导入”中隐含加入这些行为。

## 验收建议

- 任意名称、无名称、两类 Weekly goal、仅经验、仅稀有度及混合窗口；相同名称多个窗口按原始规则叠加。
- 起止 tick 当刻有效，提前一刻与过期一刻无效；有效空数组与缺失／异常数据分别处理。
- 独立人工算例：同刻经验 +10% 和 +25%，稀有度 +50% 和 +20%，结果分别 +35%、+70%，不做乘法。
- 小数加成保存往返；导入清除旧角色世界倍率；旧配置与旧脚本能力提示；异常导入保留既有整体失败原子性。
- 模拟初始化与结束刻均计入配置；热门三模式互不重复；原始经验与掉落稀有度独立对照。
- 新 userscript Worker 保存 rarityMult、单独 windows 更新及跨连接隔离；五个配置消费者兼容；战斗双语控件与本地／调试文件往返。

## 本次实际验证

执行一次临时 Node 断言探针，调用现有原始导出、战斗导入和捕获测试 harness，最终通过：

- 五个窗口包含 Weekly goal、任意活动、仅稀有度、未来和过期条目。在 tick=100，原始 windowModifiers 返回经验 1.35、稀有度 1.7，与人工加法一致。
- 相同输入当前战斗导入只得到世界经验 10%，复现非 Weekly goal 经验遗漏。
- 当前 Worker 保留全部五条窗口，但全部丢弃 rarityMult，复现捕获遗漏。
- 直接设置 manual.windows 后 normalize 结果仍为空数组，确认现有隐藏字段不能直接复用。

探针首轮误用了测试 harness 不存在的 socket 方法而失败，修正为现有 page.WebSocket 与 flushCapture 接口后完整重跑通过。未修改 harness 或产品代码；未执行完整测试、浏览器验收、真实账号验证或发布。
