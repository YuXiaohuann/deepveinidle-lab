# 采集“丢弃采集物”支持调研

日期：2026-10-16。范围：核查当前本地 1.0.1190 原始资源、采集适配层及统计口径，执行原始引擎对照；未实现页面选项、未部署。未重新联网检查游戏是否更新，也未验证服务端实际执行。

## 结论

可以增加，原始引擎已经支持，不需要修改生成文件或新增原始算法。当前页面没有此配置，`src/gathering-simulation.js` 调用 `game.startWork(..., 'bank', null)` 固定满包回仓，`gatheringDefaults` / `normalizeGathering` 也没有对应字段。只改调用参数能改变行动过程，但不能正确完成收入统计。

## 原始行为及证据

原始资源 `vendor/game-original.js` 的菜单提供 `Drop what I gather`，勾选后发送 `onFull: 'drop'`，未勾选为 `'bank'`。以下符号只对应当前快照，可在 `src/upstream.js` 中定位原样提取声明：

- `Ls`（导出 `startWork`）：将参数保存为 `route.onFull`。无输入材料的任务使用 drop 时，初始背包如有不属于当前主产物／配方额外产物的物品，会先进入回仓流程。当前实验室默认初始空包。
- `lA`：任务无法继续且无输入材料、策略为 drop 时，调用 `mP(player, J$(job))`；成功清理后发出 `dropped` 事件并继续工作。没有可丢物品则仍进入回仓流程。
- `J$`：丢弃对象为主产物和该配方 `bonus` 物品。`mP` 按基础物品 ID 匹配，删除它们的全部品质；`dropped.count` 是移除的背包条目数，不是物品数量，也没有逐物品明细。
- 因此该设置是**满包时批量丢弃**，不是每次产出立刻消失。模拟结束时可能留有未满包产物，不能把最终保留量机械设为零。
- `y7` 的完成、品质、经验、升级及偷窃被抓逻辑仍照常执行。丢弃减少回仓移动，间接改变完成次数和升级时点，不改变基础工作速度公式。
- 配方 bonus（如本次伐木样例的土豆种子）属于可丢弃对象；宠物不在这一清理集合内。`Sp` 的坐骑与 `mp` 的活动礼盒直接写仓库，也不因该策略取消。特殊奖励可能占包；无可丢物品时仍可能回仓，不能保证永不回仓。
- 偷窃的金币类任务由 `y7` 直接增加金币，不经过背包，因此该设置不会丢弃金币；另四个布料任务产出可堆叠物品，仍遵循背包与满包丢弃规则，不能把所有偷窃任务视为金币任务。

## 本次实际验证

通过 Node 内存脚本调用现有 `createGatheringScenario`、`game.predict`、`game.startWork` 和 `simulationTick`，分别传入 bank / drop，未修改应用文件。四技能各取首个任务及首个候选点：等级 1、无装备／药水／额外加成、初始空包、自动仓库、热门关闭、24 小时、seed 0；合成角色沿用当前空日／周任务规则。逐刻记录事件、经验及最终仓库／背包／溢出物品，并与原始分块离线入口 `nativeDay` 对照，8 个场景经验全部一致。

| 技能（任务／点） | 经验：回仓 → 丢弃 | 完成次数：回仓 → 丢弃 | 移动刻数：回仓 → 丢弃 | 存放事件：回仓 → 丢弃 | 丢弃模式最终保留 |
| --- | ---: | ---: | ---: | ---: | --- |
| 采矿（1／1） | 50,595 → 66,160 | 24,862 → 32,529 | 26,624 → 14 | 887 → 0 | 普通铜矿 21 |
| 钓鱼（21／25） | 50,595 → 66,160 | 24,862 → 32,529 | 26,626 → 16 | 887 → 0 | 普通虾 21（物品 20） |
| 伐木（30／56） | 55,402 → 101,164 | 18,084 → 33,038 | 58,680 → 44 | 652 → 0 | 普通原木 17（物品 10） |
| 偷窃（240／80） | 224,504 → 224,504 | 28,063 → 28,063 | 9 → 9 | 0 → 0 | 金币 168,378；另有坐骑物品 328 ×1 |

采矿／钓鱼／伐木 drop 分别出现 1,161／1,161／1,191 次丢弃事件；伐木获得的 375 个 bonus 物品 1160 全部被丢弃。偷窃两策略均被抓 224 次，均获得相同坐骑。

原始离线报告 `itemsGained` 仍记录已产出但后来被丢弃的物品。例如采矿 drop 报告累计 32,529 件，最终仅保留 21 件。因此原始 `itemsGained` 或现有适配层 `sampleItems` 不能直接作为 drop 模式的可变现数量。

本次是固定种子、四个点的机制验证，不是所有任务／点位、特殊奖励或多种子总体期望验证；没有运行全量测试、页面验收或发布检查。

## 建议实施范围（未实施）

1. 先更新采集设计中“丢弃策略不在范围”及“默认满包回仓”的对应规则和验收标准。新增一个默认关闭的“丢弃采集物”选项，旧存储默认关闭；明确清空、角色导入和技能切换的规则。
2. 在采集模型规范化、保存与控件中接入该字段，模拟调用映射为 bank / drop；复用现有配置变化取消 Worker 和重新模拟流程。原始引擎及提取闭包已包含所需功能，无需手改 `src/upstream.js`。
3. 保留原始经验、移动、完成次数、升级和被抓过程。顶部采集速度属性仍沿用原公式；减少回仓造成的效率变化由结果反映。
4. 统计区分累计产出、已丢弃与最终保留，收入排除已丢弃部分。现有 `normalItems`、`rareItems` 是累计机会期望，`totalIncome` 直接估值这些数量，必须同步调整。不能仅改 startWork 参数或在输出末尾统一置零；期末残留、配方 bonus 与特殊奖励须分别处理。保留混合期望口径时，需要另设计随实际丢弃事件结转的统计账本，并注明仍是本次随机路径下的条件期望。
5. `expectedWorkRewards` 为制造与采集共用；如修改，应保持制造默认行为并执行相关回归。优先把丢弃账本放在采集侧，复用现有奖励机会计算。
6. 专项验收覆盖四技能原始 bank / drop 对照、满包及期末残留、所有品质和 bonus 清理、金币保留、宠物占包／坐骑及礼盒直入仓库、无可丢物品回仓、点位平均与收入、旧配置／导入／双语及 Worker 失效。不能用原始离线累计产出相等代替最终资产验证。

现行功能仍按 [采集页面](../docs/pages/gathering.md)；本报告不将建议方案标记为已实现需求。
