# 角色捕获 Worker 实施与验证

## 结果与范围

本地角色 userscript 已升级为 2.6.0，解析、字段裁剪、角色／公会／窗口维护及市场深度归并均移入内置 Blob 专用 Worker。主线程保留 WebSocket 被动旁听、原始字符串转交、连接代次与积压计数、GM 保存和提示。未改应用包版本、计算模块、生成代码或原始游戏资源，未部署或更新用户已安装脚本。

角色桥接 2.4、数据协议 2、市场桥接 1.0 和两个存储键保持不变。角色字段白名单保留五个页面所需配置，含强化库存及精通收藏／锻造记录；不再保存完整角色和无关历史字段。实现前已更新 [技术设计](../docs/technical.md)，方案来源见 [调研报告](userscript-performance-research-2026-10-14.md)。

## 实现要点

- 每帧处理完后更新一次角色修订；Worker 只发小型 ACK／修订通知，主线程按需拉取最新快照。
- 每种存储最多一个拉取或保存进行中；更新在 Worker 内合并，空闲后固定等待 100ms，再读取最新状态。持续更新不推迟已安排的保存。
- 已开始的 GM 写入不可取消；连接切换后继续串行，旧写入完成后才保存新连接状态。旧完成／失败不覆盖当前提示，旧失败记录控制台。旧连接未处理原始消息仍计入积压，旧 ACK 正常扣减。
- 市场各侧保留原始接收时间，逐条合并不同物品和买卖侧；深度使用单循环取最优价，不展开巨大数组。成功提示依据实际保存快照内存在的合法报价；合并后仅剩异常报价不显示成功。
- 积压保护：128 条、16Mi UTF-16 代码单元；Worker 启动超时 5 秒、消息连续无 ACK 10 秒。创建、执行、传递、保存或过载失败均明确提示刷新，不退回主线程解析。保护值尚未依据真实账号极端流量调优。
- 提示隐藏时断开 DOM 观察；退出时终止 Worker、释放 URL 和计时器。主线程仍承担 postMessage 结构化克隆和 GM API 的序列化／存储成本，不承诺完全无卡顿。
