# 全局物品价格与市场导入方案调研

状态：方案已确认并在工作树实施，尚未发布。日期：2026-10-12。本文保留实施前调研与详细方案；当前实现及实际验证以 DESIGN.md 的全局物品价格与验证章节为准。

## 结论与范围

方案可行。建议在共用页头增加“物品价格”入口，以弹窗管理一份全局有效单价，角色 userscript 被动捕获市场报价并独立缓存；用户按分类选择最低卖单价或最高买单价，一键导入未锁定物品。锁定保护有效单价，不阻止报价缓存更新。

拟修改范围：共用页头和弹窗、独立价格存储与查询模块、角色脚本和导入桥接、战斗/采集结果估值、强化材料与底装价格读取，以及对应双语文案与验证。精通、预报和调试页可以打开价格窗口，没有物品金额计算的页面不增加额外计算功能。模拟过程、掉落数量、角色导入与调试快照计算不因改价而变化。

跨模块范围已由用户确认；已按先更新 DESIGN.md 再实现的流程实施。下文“建议/拟”描述原方案，不是未完成事项。

## 已核验现状

- `src/character-import.user.js` 已在 document-start 代理游戏 WebSocket，被动读取文本 frame 中的消息，经 GM 存储及 JSON CustomEvent 跨域传递。可复用连接观察及串行写入结构，不需要新增连接或主动发送游戏命令。
- `vendor/game-combat-update.js` 是项目于 2026-10-11 保存的公开资源 `index-C6UxPVvd.js`，来源及摘要见 `vendor/manifest.json`。其中客户端处理 `marketBook.top`、`marketBooks.tops`、`marketStock` 和 `marketDepth`。
- 报价按完整 `itemId` 区分，报价对象被界面以 `ask`、`bid` 读取。盘口对象包含 `asks`、`bids`，游戏以首档读取最佳报价。`floor` 是另一种价格，不能当作市场买单价导入。
- 市场列表针对待显示且尚未缓存的物品发送批量报价请求，`marketStock` 还包含变体及摘要信息。被动捕获无法保证一次打开市场就有全量、同一时点报价；摘要元组的完整含义本轮未核验，不建议首版解析该元组作为正式报价来源。
- 游戏有 15 个市场分类：矿石、金属锭、鱼、木材、食物、作物、药水、武器、护甲、珠宝、工具、坐骑、材料、贵重物、宝石。建议通过提取器复用原始分类定义与可交易判断，不复制物品编号区间维护另一套列表。
- `src/simulation.js` 的 `dropValue` 当前调用原始可出售判断和商人价格；战斗与采集结果保留按完整编号统计的掉落数量，也在结果中预计算商人价值。
- `src/enhancement.js` 当前独立保存碎片、卷轴、底装三项价格，空值为未定价，0 为有效值；含税总投入按现有设计对全部投入乘以 1.03。新功能不能顺带改变此税费口径。

限制：联网打开游戏首页没有取得可分析源码，本机 curl 因域名解析失败未取得最新资源。本轮没有验证 2026-10-12 线上消息、真实账号、脚本管理器或完整价格覆盖率，没有运行代码测试。上述核验仅代表保存源码的行为。

## 弹窗与价格模型

共用页头入口在所有页面可用。推荐原生 dialog，桌面宽弹窗、手机接近全屏；支持 Escape、关闭按钮、焦点约束与关闭后恢复焦点。弹窗内提供分类、名称搜索、品质和强化筛选、只看已定价/已锁定。

每行显示物品名称、品质、强化、有效单价、锁定、最近最低卖单价、最近最高买单价和报价时间。价格按完整物品编号存储；普通与传奇、+0 与 +5 不共价。分类按基础物品确定。大量装备变体按已捕获、已有定价或用户选择展示，不生成全部强化与品质组合。

每行增加勾选框，支持勾选物品及“全选当前筛选结果”，提供“批量锁定 / 批量解锁”。操作范围明确显示选中数量；全选包括当前筛选结果的全部行，不受分页或可视区域限制，不扩展到未展示的变体。改变筛选时清空勾选，避免对隐藏选中项误操作。批量操作一次性更新并保存，只改 locked，不改价格、来源或报价时间；已有相同锁定状态的条目保持不变。未定价物品也可锁定，导入时仍跳过。操作后提示实际改变数量。

推荐数据分开存储：

- 有效价格：`itemId → {price, locked, source, updatedAt, quoteCapturedAt}`。`price: null` 表示未定价，0 表示明确零价，允许有限非负数并检查计算溢出；手动编辑不自动锁定。
- 市场缓存：`itemId → {ask, bid, capturedAt}`，必要时分别保存两侧时间，避免把部分更新包装成整条新报价；空盘口是明确无报价，缺字段是未提供，二者必须区分。
- 导入偏好：每个分类选择“不导入 / 最低卖单价 / 最高买单价”。默认最高买单价，用户选定后保存偏好，后续一键复用。

每分类独立选择“买单价（商人价兜底） / 买单价 / 卖单价 / 不导入”，不再提供全局开关；武器、护甲、饰品、工具、坐骑默认不导入，其余分类默认买单价（商人价兜底）。兜底模式取商人价与最高买单价的最大值，商人价胜出或相等时显示“商人价”，明确无买单也可使用商人价。仅接受当前价格存储格式，不迁移未发布的旧全局开关。

独立 localStorage 键保存全局价格，不放入某页角色配置；跨页面共用，刷新恢复。各页清空角色配置不清空价格。保存失败显示明确提示，内存中的价格仍可使用。未知物品与无效数据不能默默转换为普通物品或零价。

## 卖价、买价与导入规则

控件按“买单价 / 卖单价 / 不导入”排列，分别使用最高买单价（bid）、最低卖单价（ask）或跳过。最低卖单价是市场卖方要价，可作为购入成本参考；最高买单价是市场买方出价，可作为立即卖出收入参考。挂单价不保证模拟数量全部成交，估值不是成交承诺。

一键导入先读取脚本市场缓存，验证协议及数据，再一次性应用：

1. 仅处理已选择分类，每个分类使用各自选定报价方向。
2. 已锁定物品始终跳过，价格、来源及更新时间都不改；用户仍可手动修改锁定价格。
3. 未捕获、缺字段或数据异常时保留原价，不启用兜底。最低卖单价明确无报价时也保留原价。最高买单价明确无报价时，兜底关闭则保留原价；兜底开启且原始可出售判断通过时，使用原始商人价格，记录来源为商人兜底及触发兜底的报价捕获时间；不可出售则保留原价并提示无法兜底。商人价格可为 0，但只能来自已核验原始函数，不由缺价推导为 0。有有效买单时，兜底开启且可出售则与商人价取最大值，商人价胜出或相等记为兜底；不可出售或兜底关闭仍使用买单价。
4. 有效报价覆盖未锁定的旧值，包括未锁定的手动价。界面明确提示该规则。
5. 旧捕获时间不能倒退覆盖更新来源的值；手动价格是否允许覆盖按第 4 条执行，不以手动编辑时间误判市场新旧。可根据已有价格的 quoteCapturedAt 拒绝倒退导入。
6. 导入结果显示实际更新（其中商人兜底数量）、锁定跳过、无报价、无法兜底、过旧及异常条目数量；读取或协议整体失败保留全部有效价格。合法报文里的局部无效条目可跳过，但必须报告。锁定及倒退校验同样适用于商人兜底。

分类使用紧凑表格，仅显示从游戏捕获的物品变体数量与平铺单选价格选项，不显示预计可导入数量及分类时间；武器、护甲、饰品、工具、坐骑默认不导入，其余分类默认买单价（商人价兜底），已有偏好保留。打开窗口异步读取缓存，无独立读取按钮；安装链接旁提供一键导入，不写“全市场已同步”。缓存存旧数据时显示年龄，不以导入按钮点击时间冒充行情时间。首版不自动清空旧价、不增加复杂过期阈值；是否限制最大行情年龄可后续确认。

## userscript 与协议

推荐扩展现有角色脚本，避免用户再装一个脚本。市场使用独立 GM 存储和独立请求/响应事件，角色协议与快照内容保持隔离；新旧脚本探测区分“角色导入可用”和“市场导入需更新”。更新脚本名称/描述与安装说明，使价格捕获范围可见。

优先捕获 `marketBook`、`marketBooks`；需要补充盘口时再处理 `marketDepth`，按完整 ID 合并缓存。仅保存物品编号、买卖报价、捕获时间及必要的协议/来源标识，不保存订单所有者、订单记录、成交历史、聊天或凭据。校验条目结构、ID、报价类型与范围；未知消息不影响游戏运行。

沿用最新连接隔离与串行写入，控制批量写入频率；新连接初始化期间阻止导入旧连接未完成写入的临时数据。历史缓存可保留，但其捕获时间必须保留，不能标记为新连接实时行情。明确无报价更新清除对应缓存侧；不抹除有效设置价格。

用户自行打开并浏览市场分类/品质/强化变体，游戏正常请求的报价才被捕获。脚本不主动翻页、不批量扫描、不下单。若希望自动抓取全量市场，需要另行研究并确认主动请求范围，不包含在此方案内。

## 各页接入与兼容

战斗/采集推荐把原商人估价开关扩展为“数量 / 商人估价 / 设置价格估价”，不从旧开关迁移。市场价格设置不修改商人模式；设置价格模式按掉落数量乘有效单价，无有效设置价格的物品标出未定价，有缺价时总收入显示“未完整定价”，可以另显示已定价部分金额。商人兜底只在用户启用并执行导入时写入有效价格，估值阶段不自行补价，也不把缺价当免费。

根据已有完整 ID 掉落数量在页面端统一估价和排序；改价、导入、锁定、语言切换不重跑 Worker，不改变模拟起点。直接金币照常加总。不新增药水、食物等成本扣除，也不将收入改名为净利润。首版价格均为税前参考价，商人和市场税费明确分开。

强化碎片、保护卷轴和所选底装默认查询全局价格；底装按当前品质与起始强化编号查询。保留“已有底装，费用为 0”的场景覆盖，避免为了已有装备修改全局商品价格。强化配置须明确保存价格模式及完整底装编号；不自动推导旧三项手动价格的模式或绑定。

当前强化税费表达沿用原有规则；保存源码中 welcome 会传 `marketTaxBp`，不能仅因价格捕获就把该字段带入既有成本公式。若需要真实市场成交含税估值，应另行核验税制及舍入规则。

## 验收与实施顺序

确认范围后先写正式设计；随后完成全局模型与弹窗、脚本市场捕获与桥接、分类导入和锁定，最后接入战斗/采集/强化，不迁移未发布设置。

针对性验证覆盖：完整编号独立定价、null/0/异常数值、保存恢复与保存失败；单项及批量锁定/解锁、筛选全选范围、切换筛选清空勾选、未定价锁定、重复锁定；分类混选买卖侧、买单兜底开关、买单与商人价较大/相等时的取值及来源、明确无买单与未捕获的区别、不可出售无法兜底、兜底来源及时间、锁定与倒退保护、导入失败原子性；单条/批量/盘口捕获、旧脚本提示、连接切换和异步写入；改价只更新金额与排序、不重跑模拟；强化缺价、零价底装和旧格式拒绝；双语桌面/窄屏及弹窗键盘操作。真实游戏验证必须检查捕获字段、分类浏览覆盖及时间提示，不能仅依靠伪造消息测试宣称行情已验证。发布前再执行完整验证。

## 详细实施方案

以下为已确认的分步实施方案。已落地 `src/item-prices.js` 纯模型、`src/item-price-store.js` 独立存储、`src/market-import.js` 只读桥接和 `src/item-price-controls.js` 共用弹窗，集成现有战斗/采集展示与强化适配层；不引入框架或状态管理依赖。弹窗实际将可折叠导入区放在筛选列表上方，方便首次使用；沿用已有页面面板、按钮、表格与配置折叠样式。实施与 122 项相关测试、Chrome/ScriptCat 真实行情验证已完成，尚未部署；实际验证范围及限制见 DESIGN.md 第 7 节。

### 第一步：固定设计与核验数据入口

1. 确认本报告的跨页修改范围，以及兜底仅在明确无买单时启用的规则。
2. 更新 DESIGN.md 共用页面章节，增加价格弹窗、批量锁定、价格持久化及导入规则；同步战斗/采集估值、强化价格来源及角色脚本协议章节。README.md 仅更新脚本升级与使用步骤。
3. 获取并核对当前公开客户端，核验 top 的 ask/bid 缺失与空值语义、盘口排序、完整物品 ID、市场分类及商人可出售/价格函数。使用真实市场消息验证，尤其确认“无买单”的表示方式。若不能核验无买单语义，商人兜底不得把缺字段作为替代条件。
4. 仅通过 scripts/extract.mjs 增加必要语义导出并重新生成 src/upstream.js；复用现有物品、品质、强化、可出售及商人价格导出。市场分类若只能来自更新资源，采用项目既有的来源记录与显式依赖流程，不为获取分类全量替换模拟引擎。

产出：正式设计基线、消息字段与来源记录、最小必要导出。此步骤不调整上游战斗/采集机制或强化税费。

### 第二步：实现价格模型与独立存储

建议新增 src/item-prices.js，承担纯数据规则：

| 接口职责 | 输入与输出 |
| --- | --- |
| 规范化价格存档 | 验证版本、完整 ID、价格、锁定及来源；异常返回明确错误或带明示警告的合法部分 |
| 查询有效价格 | 完整 ID → 数值或 null，不隐式降级到基础物品 |
| 手动编辑 | 更新指定物品价格/来源，保留锁定；清空价格后锁定仍保留 |
| 批量锁定 | 显式选中 ID 集合与目标状态 → 新状态、实际改变数量 |
| 合并报价 | 区分未提供/明确无报价/有效报价，拒绝捕获时间倒退 |
| 生成导入变更 | 当前价格、报价、分类策略 → 新价格状态与统计 |
| 掉落估值 | 数量映射与模式 → 已定价金额、完整金额或 null、缺价物品列表 |

增加轻量存储封装，可放在同模块或 src/item-price-store.js：统一读写 `dvi-item-prices-v1`，存档带 schema 版本；运行时提供一次初始化、查询、更新及订阅。更新先算完整结果，再一次替换内存状态、一次保存、通知订阅者；保存失败保留本次内存结果并显示未保存状态。无需跨页分别维护价格副本。

首次初始化为空价格表，各分类默认买单商人兜底。所有查询按同一价格表完成；筛选、勾选与弹窗开关是临时 UI 状态，导入分类偏好和兜底设置持久化。报价捕获时间不使用保存/导入时间替代。纯函数测试优先覆盖导入与估值边界，不写仅镜像 DOM 模板的测试。

### 第三步：扩展角色 userscript 和市场桥接

1. 在 src/character-import.user.js 现有 frameReceived 中增加独立市场分支，不能落入角色 capture；两类数据首次保存成功共用同样式的双语提示，后续同类捕获不重复弹出。
2. 监听 marketBook/marketBooks，必要时接入 marketDepth；提取最小报价字段，按完整 ID 更新独立市场缓存。市场缓存使用单独 GM 键，建议 `dvi-market-quotes-v1`，不向角色 snapshot 塞入行情。
3. 采用串行、合并写入的方式处理批量消息；每次异步完成前检查当前连接标识，防止旧连接覆盖新数据。捕获错误和存储失败保留明确状态；忽略不相关消息不视为失败。
4. 为市场能力提供独立 document JSON 事件，例如 `dvi-market-request/response`，只允许 probe/read；返回协议版本、报价数据和捕获状态，不接受写入或游戏操作。
5. 新增 src/market-import.js，复用 src/import-controls.js 中的超时、请求 ID 和探测思路。若值得复用则抽出小型通用桥接函数，保持角色现有事件和版本兼容；不要为此重构所有角色导入 UI。
6. 更新角色脚本发布版本及描述，明确需刷新游戏与实验室；旧脚本只缺市场能力时，角色导入继续可用，价格窗口提示更新脚本。

产出：能够独立探测并读取真实报价的市场桥接，角色与调试功能不受影响。验收复用 tests/userscript-capture.test.mjs 的脚本执行环境，补充真实结构的市场消息案例，并完成实际脚本管理器验证。

### 第四步：实现价格弹窗与批量操作

建议新增 src/item-price-controls.js；src/app.js 在页头加入入口并挂载一次窗口，src/style.css 添加响应式样式。窗口应与 render() 的整页重绘配合，保留已打开窗口、搜索/筛选、输入及状态；关闭时恢复入口焦点，语言切换不丢价格或导入设置。

窗口按以下顺序组织：

1. 标题、关闭按钮、脚本连接与报价捕获状态。
2. 分类/搜索/品质/强化/已定价与锁定筛选。
3. 选中数量、全选当前筛选结果、批量锁定/解锁。
4. 价格列表：勾选、物品、有效单价、单项锁定、买卖报价、来源及捕获时间。
5. 分类导入区：每类“买单价（商人价兜底）/买单价/卖单价/不导入”、捕获数量与一键导入按钮。
6. 操作结果及保存失败提示。

输入提交时检查价格，非法输入保留可修正文本并显示错误，不截断成 0。批量操作使用点击前已选 ID 的快照，操作过程中禁用重复提交；筛选变化清空选中集合，操作后选中集合保持，方便反向解锁。若“只看未锁定”导致操作后的条目退出结果，移除已不在筛选中的选中 ID。

导入时禁用重复读取，验证并一次应用，再更新窗口及所有页估值。关闭弹窗期间请求完成也只应用一次；若用户在读取期间手动改价或改锁，导入应用时使用最新价格/锁定状态。各分类策略在点击导入时取快照，避免处理中更改设置造成导入范围不确定。

### 第六步：接入强化价格模式

1. src/enhancement.js 保持成功率与期望数量求解独立，金额阶段接收解析后的碎片、卷轴、底装价格；单独提取价格解析函数，避免把浏览器存储依赖放进计算模块。
2. 新强化方案默认使用全局价格；底装使用所选 itemId、tier 和 current 编码，碎片与卷轴编号通过已核验原始强化材料定义确定。
3. src/enhancement-controls.js 在材料与底装区显示来源及有效单价，允许各项明确选择“全局价格 / 本方案填写”；底装另外提供“已有底装，费用 0”。本方案填写只影响当前强化方案，不写全局价格。
4. 配置必须包含明确价格模式及底装绑定，不从旧价格自动推导；格式缺失时明确报错。无全局价时仍未定价，界面显示当前使用模式。
5. 本方案底装费关联完整 ID：切换装备/品质/起始强化后，旧底装费用不应用于新 ID，新 ID 默认全局；“已有底装”也关联完整 ID。材料本方案价格可继续保留。
6. 全局价格订阅只更新使用全局来源的费用；本方案覆盖和已有底装不被导入改变。沿用缺价提示、0 数量材料无需定价、税前合计及原有 1.03 公式。

产出：统一价格可用于强化，旧方案金额保留，底装切换不会误用旧费用。补充 tests/enhancement.test.mjs 和 tests/enhancement-controls.test.mjs 的来源解析、非法旧格式及切换案例。
