# 技术方案与上游更新

### 6.1 角色导入组件与 userscript 协议

战斗、采集、制造、强化与精通复用 characterImportPanel：统一 details/summary、import-body、安装链接、按钮与状态节点，参数控制节点标识、按钮及说明；状态为空隐藏，长文本换行。导入区域使用相同高亮容器、金色标题、边框、背景与展开间距，折叠遵循 [语言、布局与持久化](shared.md#22-语言布局与持久化)。

连接检测共用单次 probe 请求，各页分别保留状态，统一由 importStatusText 生成连接成功、读取中、捕获时间及缺失/旧版本/读取失败等双语提示。较晚 probe 不覆盖读取中或已有结果；读取期间禁用对应按钮，失败保留原配置。战斗额外保留字段警告。

战斗和强化导入区域均不展示刷新读取提示；战斗页不展示配置导入说明段落，对应英文同步移除。安装／更新角色 userscript 链接与导入按钮使用一致的字号、颜色、边框、背景、宽度、高度及交互样式，保持独立一行和新标签打开行为。验收检查两页双语文案移除及链接、导入按钮样式一致。配置导入及导出无需打开游戏战斗预测列表。

- 角色 userscript 2.6.0保留安装入口、双语名称、document-start、现有游戏／线上／本机地址及共享 document 的 JSON CustomEvent 桥接；`https://*.dvi-lab.pages.dev/*` 匹配该项目的预览分支与部署地址，不扩大到其他 Pages 项目。角色桥接版本仍为 2.4，角色数据协议仍为 2，存储键 `dvi-character-snapshot-v2` 保持兼容；市场采用独立桥接与存储。
- 角色脚本旁听 own-role welcome/snapshot、公会与世界窗口，仅保存支持配置映射的字段；不安装 JSON 解析或预测字段读取钩子，不捕获预测输入。不发送游戏命令、不开额外游戏连接、不读取认证或聊天消息。
- 安装／更新脚本后刷新游戏和实验室。配置导入使用最近角色数据，显示其读取时间；跨连接／角色清空本连接状态，串行存储避免旧异步写入覆盖新数据。捕获失败、存储失败、旧协议及缺数据明确提示。
- 不维护调试专用 userscript、`dvi-debug-request/response` 桥接或 `dvi-debug-snapshot-v2` 存储读写。旧脚本管理器数据不自动读取或迁移；原有安装脚本由用户在脚本管理器自行移除。
- 协议验收：配置捕获、普通角色桥接、市场桥接、缺失／旧版／读取失败提示、预览路径、跨连接隔离及异步写入顺序继续回归；所有页面无完整快照操作，普通角色请求不接受调试来源，旧快照模拟格式明确拒绝。页面行为分别按 [战斗验收](pages/combat.md#37-验收与已知限制)、4.6 验收。

角色 userscript 的角色捕获仅处理 welcome/snapshot 中的配置，不主动运行或触发战斗预测。游戏页等待提示持续显示；角色配置存储成功后显示“角色配置已读取 / Character captured”，不引导用户打开战斗预测。角色配置和市场报价各自在本连接首次成功保存后显示双语成功提示；市场提示为“市场报价已读取 / Market prices captured”，沿用同一角落提示样式。成功提示仅显示本次捕获类型，市场成功时不附带此前角色成功提示；每种首次成功显示 5 秒，后续同类捕获继续保存但不反复显示或延长时间。清空缓存、无报价字段或仅异常报价不显示市场成功；保存完成前不显示成功，新连接重置两类提示，旧连接的延迟完成不得覆盖新状态。验收覆盖角色成功后捕获市场、两类成功提示各自 5 秒隐藏，以及后续同类捕获不改提示或延长时间。

所属公会隐藏配置：角色脚本沿用 [全局物品价格](shared.md#24-全局物品价格) 桥接，旁听 `welcome.guild` 与 `guild.info`，只保存名称 `name`、标签 `tag`，不保存成员、聊天、公告或仓库。捕获对象顶层增加 `guild`；无公会为 null，新连接及 welcome 重置，后续角色配置捕获保留本连接最近公会。战斗与强化配置导入将其写入隐藏字段 `guild` 并随各自配置持久化，不新增控件、不参与计算。旧文件缺少该字段时清空所属公会，避免沿用其他角色信息；战斗配置导入时公会字段格式错误清空并提示，强化导入仍明确拒绝并保留已有配置。验收覆盖首次捕获、公会更新/退出、跨连接隔离、两页导入与保存往返、旧文件及异常数据。已实现，角色数据协议仍为 2。


市场捕获扩展：角色脚本 2.5.2 沿用角色桥接 2.4 和数据协议 2，新增独立 dvi-market-request/response（桥接 1.0）与 dvi-market-quotes-v1 GM 存储，实验室请求仅 probe/read。被动旁听 marketBook.top、marketBooks.tops 与 marketDepth；仅保存完整 itemId、ask/bid、各侧捕获时间、异常统计及捕获状态，不保存订单、交易历史、聊天或凭据；角色导入不依赖行情。新连接清空本连接缓存并阻止旧异步写入，串行合并写入；明确无报价更新为空，缺字段不伪造无报价。用户自行浏览游戏市场分类及变体，脚本不发命令、不扫描；窗口显示捕获数量及需更新/缺数据/捕获失败提示。旧角色脚本仍可角色导入，市场能力缺失需更新。

#### 捕获 Worker（2.6.0）

- 主线程只旁听同源 `/ws`、转交原始字符串与接收时间、维护连接代次／积压计数、执行 GM 保存及提示。内置 Blob 专用 Worker 执行 JSON 解析、必要角色字段裁剪、公会／窗口状态和市场报价合并；不额外下载代码、不发送游戏指令。
- 角色仅保留所有导入消费者所需字段，包括强化的 bank/pack/overflow 和精通的 collections/forgeLog；同帧处理完成后最多更新一次角色状态。报价每侧使用原始接收时间。角色桥接 2.4、数据协议 2、市场桥接 1.0 与存储键不变。
- Worker 合并最新状态，只发小型修订通知。主线程每类最多一个请求／保存进行中，空闲后合并 100ms 再拉取最新快照；持续更新不延长已安排的等待。保存期间不回传中间快照。跨连接串行完成已开始的写入，再保存新连接状态，旧结果不显示成功。
- 原始消息积压跨连接累计，最多 128 条、合计 16Mi 个 UTF-16 代码单元；旧连接 ACK 也须扣减积压。超过上限、Worker 启动 5 秒超时、待处理消息连续 10 秒无 ACK、创建／执行／传递错误均停止捕获并显示失败，要求刷新恢复；不丢帧后继续冒充成功，不回退到主线程解析。限值是保守保护参数，尚不代表真实流量性能结论。
- 成功提示仍在实际保存成功后显示，每类每连接首次显示 5 秒；隐藏时停止全 DOM 观察。页面退出终止 Worker，释放 Blob URL；不保证关闭前最后一次异步保存完成。
- 验收覆盖真实 Blob Worker 启动与处理、全部导入字段保留／无关字段排除、同帧聚合、市场增量与独立时间、慢存储有界拉取、跨连接隔离、启动／处理失败与过载、提示时序及清理。实际脚本管理器安装和性能改善须独立记录，不能由模拟 Worker 测试代替。

### 6.4 上游更新流程

1. 保存新公开资源快照，并更新来源信息。
2. 复核并更新提取器的来源、日期、版本、SHA-256、导出映射、数据和函数签名；快照摘要不匹配、未知依赖或签名不匹配时在生成前停止提取，不能猜测替代公式。
3. 重新生成原始代码子集与摘要清单，审阅差异。仅同步已核验的局部行为时，可保留基础快照并保存补充版本完整资源，按声明原样提取、显式绑定已审阅的原依赖；manifest 分别记录两份来源、摘要、声明范围和绑定关系，不把混合提取标记为全量升级。
4. 同步 [设计索引](../DESIGN.md) 所指向的受影响规则、清单和边界，再调整适配层。
5. 通过源码一致性、计算回归、数据完整性和浏览器检查后，再同步 userscript 已核验资源位置表与模拟器允许版本；位置由该资源的实际源码行列范围确定，并通过源码摘要和声明位置回归校验，不能仅添加新文件名。更新版本说明。
